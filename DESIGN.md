# Phase 0 design note

Written before implementation. Protocol version: `0.1.0`; state version: `0.1.0`.

1. **Exact causal variable.** The handoff representation presented to the successor. Phase 1 assigns `NO_CONTEXT`, `FULL_HISTORY`, `SUMMARY`, or `FIXED_STATE` to branches of the same frozen predecessor checkpoint. Phase 2 adds `SUCCESSOR_CONDITIONED`; its comparison with `FIXED_STATE` must control handoff budget and upstream extraction. No conditioning is implemented in Phase 0.

2. **Experimental unit.** A block is a task × frozen predecessor checkpoint × exact successor model × repetition seed. Each independently restored condition branch is an outcome within that block, not an independent task sample. Analyze paired differences; repetitions do not substitute for task or model diversity.

3. **Branch invariants.** Identical original task, environment snapshot, available tools, successor system prompt, model parameters, seed policy, stopping rule, and scoring rubric. Only handoff content varies. Freeze and hash the trajectory before deriving any condition. Every branch gets its own workspace, process state, and append-only run directory. No successor can read sibling outputs. Filesystem copying alone does not isolate network services or a hostile agent.

4. **KeishoState schema.** A versioned goal and separate atomic lists for constraints/preferences, observations, verified facts, hypotheses, rejected hypotheses, actions, failed attempts, changes, open questions, uncertainties, current plan, and next actions. Every item has a stable ID, explicit epistemic status, source references, evidence references, and scope. Evidence and source records are separate. Verified claims require explicit supporting verification records; inferred claims stay inferred. Rejections and failures require scope and retry conditions; inconclusive outcomes remain distinct. Extraction validates externally supplied structured annotations; it does not infer truth or access hidden reasoning.

5. **Metrics.** Store task success (`true`, `false`, or unscored), actual transferred handoff tokens with counting method, successor action steps, and raw time/call/token/cost records. Rediscovery = annotated redundant investigations / investigation opportunities; repeated failure = scoped repeats of documented failed approaches / attempt opportunities; inherited error = annotated adoption of unsupported or false predecessor claims / predecessor-linked adoption opportunities; contradiction = unsupported contradictions of still-applicable verified knowledge / claim opportunities. Preserve counts, denominators, annotation event IDs and reasons. A zero denominator yields an undefined rate, not zero. Missing observations or prices yield unknown values, not success or free usage.

6. **Threats to validity.** Summary/extractor quality confounds representation; unequal token budgets confound efficiency; full histories may exceed context limits; state may leak ground truth; annotations may favor one condition; verified knowledge can become stale after environment changes; checkpoints can be too easy or already solved; filesystem isolation can miss caches/services; correlated branches can inflate significance; synthetic actors cannot demonstrate LLM reasoning effects. Record extraction/summary costs separately and include them in end-to-end tradeoffs. Mask condition labels when scoring behavior. Never silently truncate history or promote inference into fact.

7. **Falsification.** H1 is unsupported if structured state fails to improve paired continuation efficiency at comparable success; H2 is unsupported if conditioning does not improve held-out success/token tradeoffs or differences do not depend reproducibly on successor identity. H3/H4 require later focused removal ablations; pilot behavior alone cannot establish their causal effects. H5 is unsupported within the tested domain if full history weakly dominates all alternatives. The tiny pilot is a feasibility check, not a hypothesis verdict. Freeze effect thresholds, sample size, and analysis before the main intervention; do not select them after seeing test outcomes.

8. **Minimum viable pilot.** Exactly three deterministic debugging tasks, one predecessor, one successor, the four Phase 1 conditions, and three repetitions per task/checkpoint (36 successor branches). Fix handoff steps after a separate development calibration; retain calibration logs outside evaluation. Each task must expose a scoped dead end and an incorrect inference opportunity, with hidden deterministic success tests. Start with offline fixtures to check restoration, logs and annotations. Obtain explicit approval before paid calls. Stop now after the Phase 0 scaffold and architecture inspection.
