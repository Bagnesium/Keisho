## Concrete findings and focused changes

The prior pilot had token/call limits but no shared dollar admission ledger. The
new calibration wrapper persists a reservation before every provider attempt,
reconciles known usage conservatively, and stops the block when usage is unknown
or another reservation cannot fit. This applies only to the bounded calibration.

The prior annotation artifact omitted a complete review of uncounted actions.
The new timeline and worksheet cover every action, actual handoff and rule
decision, including uncounted regression/verification steps. Human judgments
and broader semantic counts remain pending/unknown.

The state builder accepted a separately supplied goal without proving it matched
the recorded task. The current runner already supplied the correct goal; no
actual leakage was found. A focused guard now rejects divergent/oracle goal
arguments. The valid baseline serialization remains byte-identical.

The calibration command also creates an exclusive fixed index before the first
request. Repeating that version refuses execution, preserving an unsuccessful
checkpoint instead of repeatedly sampling for a favorable one.

Files added: `src/keisho/pilot/spending.py`, `calibration_block.py`,
`calibration_review.py`, `token_audit.py`; `tests/test_readiness.py`;
`configs/calibration-task001.yaml`; prospective calibration overlay; this report,

## Leakage audit: origin of each input

| Handoff input | Actual origin | Excluded input |
| --- | --- | --- |
| SUMMARY system prompt | Existing summary-v0.1.0.txt | Private evaluator instructions |
| SUMMARY user message | Canonical frozen predecessor event tuple | Separate checkpoint-grade.json, gold, successor events |
| FIXED_STATE goal | Original task event; equality checked against caller argument | Substitute manually supplied/oracle goal |
| FIXED_STATE observations/actions/changes | Recorded public file/test tool results and action hashes | Hidden grader results and future branch outputs |
| FIXED_STATE hypotheses/rejections | Explicit external predecessor JSON claims/citations | Gold truth labels and hand-authored scripted facts |
| FIXED_STATE verified facts | Literal host public-test pass/fail observations at recorded hashes | Automatically asserted causal explanations |
| Sources/provenance | IDs/hashes/timestamps of frozen external events | Private evaluator artifacts |

This runner uses automatic deterministic projection of explicit claims/actions
and literal test observations. It does not perform general semantic reconstruction
of arbitrary prose. The Phase 0 `extract_state` function alone is annotation
ingestion/validation; here its annotations are generated by the gold-blind builder,
not supplied manually. Confidence 0.5 is a fixed placeholder, not calibrated belief.
Model certainty is not independently promoted; rejections remain UNCERTAIN.

Gold is loaded after sealing for eligibility/scoring; hidden results are saved
outside that trajectory. The focused regression inserts a canary into private
gold and hidden expected results, proves it appears in the private checkpoint
grade, and checks its absence from state/capsules/all model requests. Rebuilding
state after successor completion yields the identical saved state. Scripted
fixtures deliberately use evaluator knowledge to construct test behavior, but
are imported as execution models only in explicit offline mode. The production
calibration factory uses the existing OpenAI adapter.

Agent file/tool access and isolated workers exclude gold, raw logs, review files,
sibling content, outside file data, writes from test code, network and forks.
No private evaluator artifacts are copied to agent workspaces.

Metadata and syntax account for approximately 84–87%. Each test fact, evidence,
failed attempt and action repeats provenance/scope, often the complete source-hash
map. Source registries add event hashes/locations and references. State additionally
represents observations/actions/changes/facts/evidence separately. It is a verbose
audit representation; no minimality or compression benefit has been established.

Counting uses pinned tiktoken0.12.0/o200k_base and the hash-checked vocabulary.
The audit reconstructs and verifies unchanged canonical state bytes from each
sealed saved trajectory, tokenizes the full text once, labels every UTF-8 byte
by JSON path and divides each token's weight proportionally across its byte
labels. Exact duplicate semantic/evidence leaf values after their first occurrence
go in the duplicate row. Repeated administrative values remain metadata; partial
or semantic overlaps are not estimated. JSON keys, punctuation, quotes and escape
syntax are overhead. Evidence/action-result strings include visible source/test
output. These allocations are an explicit estimate, not independently tokenized
fragments or provider-reported usage. Provider usage is unavailable here.

[Machine-readable attribution](token-overhead-v1.0.0.json) stores method,
category definitions, bytes, totals and duplicate paths. Any future compact
baseline would require a new serializer/prospective amendment. None was implemented.

## Execution and spending proposal

Exact command, **only after explicit approval and an API key are provided**:

```sh
./keisho calibration-block --config configs/calibration-task001.yaml --approve-live
```

[Configuration](../configs/calibration-task001.yaml) pins the existing task and
pilot configuration hashes. [Plan](one-block-calibration-plan-v1.0.0.json) contains
exact prompts/model IDs and cost assumptions. Predecessor/summary:
`gpt-4.1-mini-2025-04-14`; successor: `gpt-4.1-2025-04-14`. Both requested and
returned IDs are retained; no substitution. State projection costs zero model
calls. Existing predecessor/successor budgets remain 9/14 model calls, 9/12 tools,
2,048 output per call, 60,000 combined tokens per trajectory, 32,000 per-request
input and 128,000 context caps. Summary output cap: 1,024. Handoff cap: 24,000.

| Stage | Max calls | Input allocation at max outputs | Max outputs | Combined-token envelope | Cost envelope |
| --- | ---: | ---: | ---: | ---: | ---: |
| Predecessor | 9 | 41,568 | 18,432 | 60,000 | $0.0461184 |
| Summary; state projection adds zero calls | 1 | 32,000 | 1,024 | 33,024 | $0.0144384 |
| Four successors | 56 | 125,312 | 114,688 | 240,000 | $1.168128 |
| Total | **66** | | | **333,024** | **$1.2286848** |

These are cost-maximizing allocations within combined-token limits, not independent
input/output maxima or average spend. Complete cumulative context, including
repeated handoff/task/tool history, is billed every call and included in guards.
No cache discounts are assumed. Official default rates checked 2026-10-03:
[mini $0.40/$1.60 per million input/output](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[GPT-4.1 $2/$8](https://developers.openai.com/api/docs/models/gpt-4.1).

Proposed API-usage cap: **$1.25 before taxes**, shared across all stages. Before
transport, reserve the full allowed 32,000 input tokens plus the requested output
maximum at noncached rates: $0.0160768 for a predecessor request, $0.0144384 for
summary, $0.080384 for a successor request. Reconcile reported usage at noncached
rates and release unused dollars; actual provider/invoice cost is separate.
Unknown/out-of-bound usage retains the reservation and halts. Insufficient dollars
prevent transport. Failures are not retried; no credential-validation call occurs.
Reservations can stop a request conservatively even if its eventual actual charge
would have fit. That stop is preserved, never worked around or resampled.
Admission denials are explicitly marked not transmitted. Existing generation-call
counts include initiated attempts; the ledger separately identifies admitted
requests when reconstructing provider execution and spend.

One genuine predecessor will investigate freely. The existing nine-tool rule is
applied without forcing a trace/dead end. Solved/early-finished, uninformative or
ineligible outcomes stop before summary/successors. An eligible checkpoint supplies
one identical snapshot to all four branches. Seed17 order is NO_CONTEXT, SUMMARY,
FULL_HISTORY, FIXED_STATE. Unknown spending stops remaining branches. Real results
live in `runs/real-calibration/`, excluded from later evaluation.
