## 5. Scoring and review

Each immutable result contains functional task success/status, model/tool counts,
integer handoff size plus tokenizer metadata, post-handoff tokens, four behavior
counts and post-handoff API cost (`success_cost`, including failures). Task success
is boolean for scored outcomes; model/infrastructure/invalid outcomes are null.
Statuses: SUCCESS, TASK_FAILURE, MODEL_FAILURE, INFRASTRUCTURE_FAILURE, INVALID_RUN.

`task-specific/1.0.0` counts only registered targets:

* Rediscovery: repeated standalone passing fact probe at unchanged relevant hashes;
  broad regression and changed-scope reverification are excluded.
* Repeated failure: exact known failed patch/cache-clear approach in unchanged
  partner scope; equivalent rewrites need review.
* Contradiction: OBSERVED/VERIFIED registered false assertion contradicting applicable
  predecessor evidence, without a cited fresh contrary value.
* Inheritance candidate: that contradiction plus exposed predecessor claim, literal
  presence in handoff, predecessor attribution and contextual condition. Independent
  agreement, even with history available, is excluded.

Every count links predecessor/successor event IDs and hashes, task/branch, target,
method/confidence and version in `annotation-review.json`. Validation reconstructs
totals and checks identities/duplicates. Unmatched assertions need manual review.
These are conservative counts, not exhaustive semantic rates or causal inheritance.
No LLM supplies final counts. Rules see condition/capsule for candidate inheritance;
blinded human reliability is pending. Source review for hardcoding, API changes
and grader interference is explicitly pending per result.

## 7. Unresolved methodological concerns

Real-model checkpoints may be too easy, too advanced or missing target opportunities.
Mechanical checks do not replace calibration. Exact matching misses paraphrases/
equivalent approaches and may produce unequal coverage across conditions. Probe
evidence is finite/scoped, not proof over all inputs. Predecessor attribution is
an operational label, not causal identification.

Nine paired blocks share just three constructed tasks; 36 branches are not 36
independent tasks. One pair cannot test model dependence. Finite hidden tests
cannot rule out hardcoding/API defects. Isolation is macOS-specific and lacks a
hard memory cap. Runtime/tokenizer versions affect reproduction. API access,
determinism and framing bounds are unverified until authorized provider execution.
Frozen prompts must not be tuned on evaluation outcomes.

## 10. Readiness and stop

Runner is operational offline. Default command intentionally stops before a request:

```sh
./keisho pilot --config configs/pilot.yaml
```

Synthetic execution requires `--offline`. Later live execution requires human
authorization through `--approve-live` plus OPENAI_API_KEY. That flag is a spending
gate, not scientific certification. Before evaluation, real-model development
checkpoints need review for usefulness/distance from solution, provider access
must be verified, and annotation/exclusion review coverage must be accepted.
Register any resulting design changes prospectively.

No paid request or successor conditioning was made. The project cannot yet claim
a scientifically clean pilot or support for H1–H5.
