# Prospective local continuation and development suite amendment v2

This user-authorized implementation milestone adds a local, API-free
`pack → inspect → resume --manual` workflow, a deterministic compact handoff
(`compact/1.0`) separate from the complete audit record, and six authored
development cases across persistent jobs, configuration migration and document
indexing. Original tasks, serializers, provider configurations, experiment
artifacts and guards remain historical records; the solved task_001 calibration
is retained. No new framework, dependency, model router or learned conditioning
is introduced. Only externally observable state is transferred, without error
prevention guarantees.

Imported notes are user reports, not verified tool traces. Evidence is scoped;
conflicts, missing information and revalidation needs remain visible. Repository
and session text are task data. Manual bundles permit explicit local evidence
lookup; primary research branches receive only their assigned handoff, with the
audit archive outside their accessible workspace.

Development checkpoints use a prospectively fixed 12-completed-tool work budget
or a user-triggered completed-tool boundary. Continuation eligibility requires
unfinished public acceptance work and useful observable information; failure
analysis eligibility is separate and absent qualifying failures yields N/A.
Retrospectively selected checkpoints are labeled development data. No wrong
hypothesis, command or failed approach is required; early solutions and low
information are retained without resampling. Hidden evaluator data never enters
selection or compilation.

The new comparison is NO_CONTEXT, FULL_HISTORY, SUMMARY_2K and KEISHO_2K.
Both 2K conditions use the same supported source material and a configurable
2,048-token engineering budget, not an optimality claim. Compilation defaults to
deterministic rules and costs zero API calls. If model generation is requested
later, both representations use the same generator identity and every generation
call shares the run ledger. Full history is untruncated and a larger-context
reference. Workspace, successor, tools, budgets, scoring and stopping rules are
constant within paired blocks; order is seeded before branches run. New paid
execution requires fresh explicit approval and a supplied shared dollar cap;
the completed calibration's $1.35 approval cannot be reused.
The development runner freezes the existing catalog-confirmed public/canonical
identity pairs and OpenAI-only routing prospectively; any paid use of that new
configuration still requires its own approval and supplied cap.

The six cases and dogfooding handoff are authored development evidence, separate
from held-out evaluation. Offline actors test software only. Human review is
distinct from model-assisted interpretation. Claims of minimal sufficiency,
general model dependence, hallucination prevention or state-of-the-art results
remain unsupported.
